# Bitrix24 Open Lines automation

This integration receives Bitrix24 outbound webhook events and evaluates only the
chat/deal that triggered the event. It defaults to `dry_run`, so it reports what
it would do without taking chats, moving deals, or sending messages.

## Environment

```bash
BITRIX_WEBHOOK_BASE_URL=https://your-domain.bitrix24.mx/rest/USER_ID/WEBHOOK_KEY
BITRIX_ASSIGNMENT_STAGE_ID=C16:UC_GIKKS8
BITRIX_CATEGORY_ID=16
BITRIX_AUTOMATION_MODE=dry_run
BITRIX_OUTBOUND_TOKEN=
BITRIX_OPERATOR_USER_ID=2381716
BITRIX_TARGET_STAGE_ID=C16:UC_L8W7U1
BITRIX_GREETING_MESSAGE=Hola, gracias por escribirnos. Te atiendo en un momento.
```

Optional:

```bash
BITRIX_ALLOWED_CONNECTORS=ank_chats_app24_ca_whats_app,bitrix_whatcrm_net_70680444
```

## Endpoints

- `GET /`
- `GET /api/bitrix/health`
- `POST /api/bitrix/events`
- `POST /api/bitrix/check`

Use `/api/bitrix/events` as the handler URL for a Bitrix24 outbound webhook.
Use `/` as the web dashboard. If `BITRIX_DASHBOARD_TOKEN` is set, open it with
`/?token=YOUR_TOKEN`.

## Render Free deploy

On Render, create a **Web Service**.

Recommended settings:

```text
Root Directory: apps/api
Build Command: pip install -r requirements.txt
Start Command: uvicorn address_ai.api.main:app --host 0.0.0.0 --port $PORT
Health Check Path: /api/health
```

Environment variables:

```bash
BITRIX_WEBHOOK_BASE_URL=https://your-domain.bitrix24.mx/rest/USER_ID/WEBHOOK_KEY
BITRIX_ASSIGNMENT_STAGE_ID=C16:UC_GIKKS8
BITRIX_CATEGORY_ID=16
BITRIX_AUTOMATION_MODE=dry_run
BITRIX_DASHBOARD_TOKEN=choose-a-private-token

BITRIX_OPERATOR_USER_ID=2381716
BITRIX_TARGET_STAGE_ID=C16:UC_L8W7U1
BITRIX_GREETING_MESSAGE=
```

After deploy, open:

```text
https://your-render-service.onrender.com/?token=choose-a-private-token
```

Put this URL in Bitrix24 outbound webhooks:

```text
https://your-render-service.onrender.com/api/bitrix/events
```

## Recommended Bitrix24 events

Start with one outbound webhook for CRM events:

- `ONCRMDEALADD`
- `ONCRMDEALUPDATE`

If your portal exposes Open Lines events in outbound webhooks, add:

- `OnOpenLineMessageAdd`
- `OnImConnectorDialogStart`

Bitrix events often send only IDs. The API handler uses that ID to fetch the
current deal, linked chats, and chat history, then makes the decision.

## Modes

`BITRIX_AUTOMATION_MODE=dry_run`

- Validates the condition.
- Returns `candidate` or `ignored`.
- Does not answer the dialog.
- Does not update CRM.
- Does not send messages.

`BITRIX_AUTOMATION_MODE=live`

- Rechecks the chat history.
- Calls `imopenlines.operator.answer`.
- Rechecks again to reduce race-condition risk.
- Updates `assignedById` and `stageId` when configured.
- Sends `BITRIX_GREETING_MESSAGE` when configured.

## Public URL for tests

For local tests, expose the API with a tunnel:

```bash
uvicorn address_ai.api.main:app --app-dir apps/api --reload --port 8000
cloudflared tunnel --url http://localhost:8000
```

Then set the Bitrix outbound webhook handler to:

```text
https://your-public-tunnel.example/api/bitrix/events
```

## Safety notes

- Keep `BITRIX_AUTOMATION_MODE=dry_run` until event payloads look right.
- Set `BITRIX_OUTBOUND_TOKEN` to the token generated by the outbound webhook.
- Delete test webhooks after testing and create a fresh one for live mode.
- Keep the inbound webhook URL secret. It can read and modify data according to
  the permissions granted in Bitrix24.
